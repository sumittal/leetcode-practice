# 1286. Iterator for Combination

**Difficulty:** Medium  
**Tags:** String, Backtracking, Design, Iterator  
**Companies:** Google  
**Pattern:** String  
**LeetCode:** [https://leetcode.com/problems/iterator-for-combination/](https://leetcode.com/problems/iterator-for-combination/)

## Problem

Design the `CombinationIterator` class:

- `CombinationIterator(string characters, int combinationLength)` Initializes the object with a string `characters` of **sorted distinct** lowercase English letters and a number `combinationLength` as arguments.
- `next()` Returns the next combination of length `combinationLength` in **lexicographical order**.
- `hasNext()` Returns `true` if and only if there exists a next combination.

**Example 1:**

```

**Input**
["CombinationIterator", "next", "hasNext", "next", "hasNext", "next", "hasNext"]
[["abc", 2], [], [], [], [], [], []]
**Output**
[null, "ab", true, "ac", true, "bc", false]

**Explanation**
CombinationIterator itr = new CombinationIterator("abc", 2);
itr.next();    // return "ab"
itr.hasNext(); // return True
itr.next();    // return "ac"
itr.hasNext(); // return True
itr.next();    // return "bc"
itr.hasNext(); // return False

```

**Constraints:**

- `1 <= combinationLength <= characters.length <= 15`
- All the characters of `characters` are **unique**.
- At most `10^4` calls will be made to `next` and `hasNext`.
- It is guaranteed that all calls of the function `next` are valid.

## Approach

### Intuition

Lexicographic combinations are generated by advancing the rightmost index that can still move.

### Brute Force

Generate all subsets and filter by the requested length.

### Optimal

Keep only the current increasing index tuple and advance it like an odometer.

| Approach | Time | Space |
| --- | --- | --- |
| Brute Force | construction O(2^n), next O(1) | O(2^n) |
| Optimal | next O(k), hasNext O(1) | O(k) |

### Edge cases

- The first tuple contains the earliest k characters.
- After the last combination, hasNext is false.
